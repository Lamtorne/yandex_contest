# Выноски на 3D-модели

## Как работать

1. Клонируйте этот репозиторий к себе, чтобы писать решение локально
2. Коммитьте решение в ветку `main` и пушьте в свой репозиторий
3. Отправьте посылку в интерфейсе Контеста: проверяющая система заберёт состояние вашего репозитория и прогонит по нему публичные и скрытые автотесты
4. Балл посылки — прогресс относительно исходного состояния репозитория с учётом весов критериев: неизменённый стартер даёт 0 баллов, полностью выполненная задача — максимальный балл. Публичные тесты лежат в `tests/public` и запускаются локально командой `npm test`
5. Прохождение всех публичных тестов не означает максимальный балл: значительная часть проверок скрыта
6. Постарайтесь исправить как можно больше проблем в коде проекта. Критериев много: расставляйте приоритеты и следите, чтобы уже работающее не сломалось

## Задача

Карточка товара в каталоге показывает 3D-модель умной колонки. Покупатель вращает её мышью
и переключает вариант товара (цвет корпуса, комплектация). К точкам корпуса привязаны
аннотации-выноски: маркер на якоре, соединительная линия и подпись слева или справа.

Карточка показывает **две сцены** одной модели — общий вид и вид сверху. У каждой своя
камера, но набор аннотаций у них общий: он приходит с сервера для выбранного варианта.

Работы две:

1. **`src/layout.ts`** — раскладка выносок внутри одной сцены.
2. **`src/calloutController.ts`** — общий владелец состояния аннотаций карточки.

Продуктовые требования заказчика:

- «аннотации читаются как статичная схема из каталога, а не мигают, пока покупатель
  поворачивает модель»;
- «при переключении варианта карточка не должна моргать пустотой: пока грузится новый
  набор, покупатель видит прежний»;
- «если сеть подвела, аннотации не должны исчезать — показываем ошибку поверх того, что
  уже есть, и даём повторить».

## Модель сцены

Камера вращается по орбите вокруг центра модели. Азимут и высота задаются в градусах,
высота ограничена диапазоном ±85°.

```text
orbit = (cos(el)·cos(az),  sin(el),  cos(el)·sin(az))   — направление на камеру
d     = −orbit                                          — направление взгляда
right = unit(d × (0,1,0)),  up = right × d              — базис плоскости экрана

screen.x = width/2  + SCENE_SCALE · (P · right)
screen.y = height/2 − SCENE_SCALE · (P · up)
depth    = P · d                                        — меньше значит ближе к камере
```

Корпус — эллипсоид с центром `shape.center` и полуосями `shape.radii`. Якорь виден, когда
нормаль поверхности в нём направлена навстречу камере.

Всё это уже реализовано в `src/projection.ts` — файл менять нельзя.

## Критерии приёмки

1. Подписи видимых выносок не накладываются друг на друга; между соседними подписями
   остаётся зазор не меньше `LAYOUT.gap`
2. Подпись целиком помещается в кадр и не подходит к его краю ближе чем на `LAYOUT.margin`
3. Выноска, чей якорь ушёл на дальнюю сторону корпуса, помечена как скрытая и не рисуется
4. Подпись отстоит от якоря по горизонтали на `LAYOUT.leaderLength`; при нехватке места по
   вертикали она смещается шагом `LAYOUT.labelHeight + LAYOUT.gap`, сначала вниз, затем вверх
5. Выноски раскладываются в порядке убывания `priority`: у более приоритетной выноски
   подпись ближе к желаемой позиции. При равном `priority` порядок задаётся `id`
6. Подпись меняет сторону только после того, как её якорь зашёл за вертикальную ось кадра
   дальше чем на `LAYOUT.sideSwitchMargin` пикселей. Пока якорь колеблется в этой полосе,
   подпись остаётся на прежней стороне
7. Повторный вызов раскладки с тем же положением камеры не меняет результат
8. Скрытая выноска не занимает место в раскладке видимых, но помнит свою сторону

### Аннотации варианта

9. При переключении варианта набор на сцене остаётся прежним, пока не придёт успешный
   ответ; `phase` при этом `loading`, а `shownVariantId` продолжает указывать на показанный
   набор
10. Ответ, относящийся к варианту, который уже не выбран, не применяется никогда — даже
    если пришёл последним
11. Источник нумерует ответы сквозным `revision`, общим для всех вариантов: набор с
    `revision` не больше показанного игнорируется, к какому бы варианту он ни относился
12. Ошибка запроса переводит `phase` в `error` и заполняет `error`, но **не** убирает уже
    показанные аннотации; `retry()` повторяет запрос выбранного варианта
13. `subscribe` возвращает функцию отписки; после `dispose()` подписчики не вызываются
14. Обе сцены карточки показывают один и тот же набор аннотаций в любой момент времени

### Единый указатель аннотаций

Аннотации появляются в четырёх местах: две сцены, легенда под ними и текст спецификации,
который покупатель копирует.

У сцен разные камеры, поэтому одна и та же выноска может быть видна на одной сцене и
скрыта на другой.

15. `buildCalloutIndex(callouts, layouts)` строит указатель: порядок задаётся убыванием
    `priority`, при равном значении — возрастанием `id`; номер равен позиции в указателе,
    считая с единицы
16. Номер выноски одинаков во всех четырёх местах и не зависит ни от камеры, ни от того,
    на какой сцене выноска видна
17. `visibleOn` перечисляет сцены, где выноска видна прямо сейчас; на отдельной сцене
    номера идут с пропусками — это нормально
18. Легенда под сценами и текст спецификации показывают состав варианта; спецификацию
    покупатель копирует в буфер обмена. Строка выноски, не видной ни на одной сцене,
    помечается классом `legend-offscreen` и вместо перечня сцен показывает «не видна с
    этого ракурса»
19. Порядок пунктов в спецификации совпадает с порядком в легенде

### Ширина подписей

Жалоба поддержки: «на варианте „Графит Pro" подписи наезжают друг на друга и вылезают за
плашки, на базовом варианте всё выглядит аккуратно». Воспроизводится в живом приложении:
`npm run dev`, переключите вариант и присмотритесь к длинным подписям.

20. Плашка подписи обнимает свой текст: ширина равна ширине отрисованного текста плюс
    `LAYOUT.labelPaddingX` с каждой стороны
21. Ширина плашки не превышает `LAYOUT.maxLabelWidth`; более длинный текст ужимается в
    доступную ширину
22. Когда реальная ширина текста недоступна (среда без метрик текста), используется
    `LAYOUT.labelWidth`
23. Зазоры, удержание в кадре и все остальные правила раскладки действуют для фактической
    ширины каждой плашки. Правило одинаково для обеих сцен, хотя у них разные вьюпорты и
    разный масштаб отображения; типографика подписи задана в `style.css` и меняться не
    должна

### Закреплённые аннотации

Покупатель может закрепить важную для себя аннотацию — кликом по её маркеру на сцене или
по строке легенды. Закреплённая аннотация не исчезает со сцены, даже когда её точка
уходит на дальнюю сторону корпуса: подпись остаётся на экране в приглушённом виде, а её
линия ведёт к краю силуэта корпуса в направлении спрятанной точки. Снимается закрепление
повторным кликом.

24. Закреплений может быть несколько; каждое живёт, пока покупатель его не снимет
25. Закрепление переживает вращение модели и переключение варианта, если у нового
    варианта есть аннотация с тем же идентификатором; если такой аннотации нет —
    закрепление тихо снимается и при возврате на прежний вариант само не
    восстанавливается
26. В легенде закреплённые помечены; пометка держится и когда выноска не видна ни на
    одной сцене
27. Закреплённая подпись, чей якорь скрыт корпусом, участвует в раскладке наравне с
    видимыми: занимает место, соблюдает зазоры и не выходит за кадр; точка на краю
    силуэта берётся из `modelSilhouette` в направлении якоря
28. Всё, что работало до этой фичи, продолжает работать ровно так же: закрепление —
    добавка к карточке, а не её перестройка

Контракт: `togglePin(calloutId)` у контроллера, `pinnedIds` в `CalloutState`, `pinned`
в `PlacedCallout` и `CalloutIndexEntry`, седьмой аргумент `layoutCallouts`.

### Подробности аннотации

Покупатель нажимает на подпись и читает подробности: материал, размеры, совместимость.
Подробности приходят отдельным запросом на пару «вариант + аннотация» и кэшируются, пока
карточка открыта.

Жалобы поддержки: «раскрыл подробности, переключил цвет — увидел описание от прежнего
цвета»; «вернулся к первому цвету, а подробности загружались заново»; «переключил цвет,
пока грузились подробности, и карточка показала описание не той аннотации».

29. Раскрыта не более одной аннотации; повторный вызов `toggleDetail` для неё сворачивает
    подробности, вызов для другой — переключает на неё
30. Подробности принадлежат **показанному** набору: пока на сцене прежний вариант, его
    подробности остаются на экране; вместе с применением нового набора подробности
    перестают относиться к прежнему варианту
31. Раскрытие переживает смену варианта, если аннотация с тем же `id` есть в новом наборе;
    если её там нет — подробности сворачиваются и сами не восстанавливаются
32. Уже загруженные подробности пары «вариант + аннотация» показываются сразу, без
    промежуточной загрузки и без повторного запроса
33. Ошибка загрузки набора не сворачивает раскрытые подробности: на экране остаётся
    прежний набор, значит и его подробности тоже
34. `toggleDetail` для аннотации, которой нет в показанном наборе, ничего не делает
35. Подробности открываются кликом по подписи выноски — по всей её площади, включая текст

### Вращение модели

Жалоба поддержки: «кручу модель мышкой, а она поворачивается не в ту сторону — тяну
вверх, а она заваливается на меня».

36. Модель поворачивается вслед за курсором, как будто покупатель вращает её рукой:
    перетаскивание вверх наклоняет модель **от** зрителя, открывая днище корпуса;
    перетаскивание вниз наклоняет её к зрителю, открывая верхнюю панель. По горизонтали
    модель следует за курсором так же: тянете вправо — модель поворачивается вправо

Контракт: `toggleDetail(calloutId)` у контроллера, `detail: { calloutId, phase, body }` в
`CalloutState`, `loadDetail(variantId, calloutId, signal)` у источника.

Требования 1–2 имеют приоритет над требованием 6: если сохранение стороны приводит к
наложению подписей, конфликт разрешается смещением подписи по вертикали.

## Публичный контракт

### Раскладка

`layoutCallouts(callouts, shape, camera, viewport, previous, labelWidths?)` возвращает
`PlacedCallout[]` — по одной записи на каждую входную выноску, в том же порядке.

Пятый аргумент `previous` — результат предыдущего вызова раскладки или `null` при первом
вызове. Сцена передаёт его при каждом изменении камеры. Шестой аргумент `labelWidths` —
ширины текста подписей по id выноски (`LabelWidths`) или `null`, когда измерения
недоступны.

### Контроллер аннотаций

`createCalloutController(source, initialVariantId)` возвращает `CalloutController`:

```ts
getState(): CalloutState;
subscribe(listener: () => void): () => void;  // возвращает функцию отписки
selectVariant(variantId: string): void;
retry(): void;
dispose(): void;
```

`CalloutState` описывает состояние всей карточки сразу:

```ts
selectedVariantId: string;        // что выбрал покупатель прямо сейчас
shownVariantId: string | null;    // к какому варианту относится набор на экране
phase: 'loading' | 'ready' | 'error';
revision: number;                 // ревизия показанного набора
callouts: readonly Callout[];
error: string | null;
```

`selectedVariantId` и `shownVariantId` — разные вещи и во время загрузки различаются.

`CalloutSource.load(variantId, signal)` — один вызов равен одному сетевому запросу.
Источник нумерует ответы: каждый следующий ответ получает больший `revision`.

Типы: `src/types.ts`. Константы раскладки: `LAYOUT` в `src/projection.ts`.
Данные модели: `src/fixtures.ts`. Источник аннотаций: `src/calloutSource.ts`.

## Ограничения

Нельзя изменять:

- `src/types.ts` — публичные типы
- `src/projection.ts` — проекция, видимость якоря и константы раскладки
- `src/fixtures.ts` — данные модели и аннотаций
- `src/SpeakerModel.tsx` — отрисовка корпуса колонки
- `src/weave.ts` — плетение акустической ткани на корпусе
- `src/calloutSource.ts` — источник аннотаций (фейк каталога)
- `style.css` — визуальный контракт карточки: типографика подписей задана здесь
- `package.json`, `package-lock.json` — зависимости зафиксированы
- `vitest.config.ts`, `playwright.config.ts`, `playwright.shared.ts`, `tsconfig.json` — конфигурация тестов
- `tests/setup.ts` — полифилы тестового окружения
- `.gitignore`

Внешние библиотеки подключать нельзя: раскладка считается вручную.

## Локальные пререквизиты

Перед началом работы подготовьте локальную среду:

- Нужны `Node.js 24.x` и `npm`
- Перед первым browser-run выполните `npx playwright install chromium`
- Если Playwright на Linux попросит системные зависимости, используйте `npx playwright install --with-deps chromium`
- Для `e2e` и локального dev-сервера держите свободными порты `4173` (Playwright) и `5173` (Vite)
- Базовые файлы из `.gitignore` (секция `# readonly`) менять нельзя: скрытые тесты и CI рассчитывают именно на них

## Разработка

1. Установить зависимости:
```bash
npm install
```

2. Запустить тесты:
```bash
npm test
```

`npm test` запускает unit + e2e.

Отдельно только unit:
```bash
npm run test:unit
```

Отдельно только e2e:
```bash
npm run test:e2e
```

Для тестирования в режиме наблюдения за изменениями в коде:
```bash
npm run test:watch
```

3. Запустить рабочую копию:
```bash
npm run dev
```
